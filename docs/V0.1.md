# Graphcraft v0.1 implementation report

Status: runnable local alpha
Date: July 22, 2026

## Acceptance boundary

Version 0.1 is the first executable Graphcraft slice. It is accepted as an alpha when it can:

1. compile and display a user-owned run contract;
2. persist an execution graph and governance anchors;
3. isolate writes in a new Git worktree;
4. invoke either supported host through structured, non-interactive output;
5. verify work with deterministic repository probes;
6. checkpoint every transition in a hashed event log;
7. rebuild corrupted state and recover interrupted running or waiting nodes without repeating accepted nodes;
8. distinguish measurable progress from unchanged work and stop safely;
9. expose the same lifecycle through a CLI and a small MCP surface; and
10. stay below the planned 250-token plugin discovery limit.

This minimum acceptance boundary did not require review, comment, or check-rerun mutations beyond a normal non-force push and idempotent PR creation. The current alpha now implements exact review replies/resolutions and justified check reruns, while PR editing/reopening, merge, deployment, and stable-release performance claims remain excluded.

## Implemented architecture

The pnpm workspace separates:

- `core`: schemas, graph compilation and validation, context capsules, event hashing and replay, progress leases, and host interfaces;
- `runtime`: event storage, atomic materialized views, locks, worktrees, deterministic waits, detached supervision, scheduling, recovery, general graph amendments, and run lifecycle;
- `probes`: shell-free command execution, file checks, Git evidence, repository test discovery, runtime-owned GitHub snapshot specifications, and workspace hashing;
- `adapter-codex` and `adapter-claude`: capability and authentication checks, structured worker execution, normalized events, and token usage;
- `github`: bounded `gh` capability checks, read-only fully paginated SHA-bound snapshots, and explicit PR-create, review-reply, thread-resolution, and check-rerun mutations;
- `cli`: installation, contracts, lifecycle controls, and human or JSON rendering; and
- `mcp`: one low-discovery-cost tool covering run, status, inspect, probes, durable control decisions, resume, pause, stop, trace, and doctor actions.

The runtime also exposes an experimental matched benchmark harness. It is evaluation infrastructure, not evidence that the stable efficiency target has been met.

The event log is the source of truth. `state.json` and `graph.json` are rebuildable views. Workers can change repository files but cannot edit the approved contract or governance anchors.

A real-host dogfood run used the bundled CLI against a disposable repository. The initial Codex child was unavailable because that shell CLI was not authenticated; Graphcraft stopped without claiming progress. The same persisted run resumed with authenticated Claude Code. The worker made the requested implementation and tests, the parent process was interrupted, and a second resume recovered the stale lock and existing worktree. Independent `npm test` verification passed three tests, including the requested empty-input behavior, and the run reached `completed`.

The bundled MCP server was also exercised through a real TypeScript MCP client: initialization, tool discovery, and a structured `doctor` call all succeeded. Both Codex and Claude plugin manifests pass their native validators.

Current live adapter evaluation also covers Codex CLI 0.144.6: bug, feature, migration, refactor, and audit prompts produced five distinct valid repository-grounded graphs; an exact session resumed after the first process was terminated; and isolated semantic verification returned grounded evidence without changing its fixture. Graphcraft's public command behavior continues to invoke the ordinary `codex` executable.

The public `@tpypan/graphcraft@0.1.1` package was installed into a clean global prefix and executed successfully. Both `npm exec --package @tpypan/graphcraft` and `npx @tpypan/graphcraft` resolved the public package and reported the expected version from an empty directory.

## Token posture

The Codex plugin discovery metadata is checked in CI and currently estimates below 250 tokens. Worker calls receive a content-addressed context capsule rather than prior transcripts or raw logs. Polling, Git inspection, hashing, graph traversal, state replay, and status output are deterministic and do not require model calls.

The real-host dogfood produced token receipts. Graphcraft now preserves provider limitations explicitly and reports normalized whole-run, phase, and node costs. Its benchmark harness can gather matched receipts, but no complete repeated dual-host result or blinded defect review has been accepted. Version 0.1 therefore makes no claim that it has reached the stable plan's 20% median savings target.

## Known limitations

- `local_verified`, `committed`, `pushed`, `pr_open`, and `pr_green` execute. Remote finish lines require an authenticated writable GitHub preflight, use a run-specific non-force branch, and bind every observation to the exact pushed head and current base. Review and actionable CI failures can trigger bounded reverified repair pushes; exact replies/resolutions and justified check reruns are journaled; sticky human decisions, non-rerunnable checks, uncertain rerun dispatch, and base conflicts stop safely. Broader remote requests fail clearly instead of being silently narrowed.
- Codex and Claude CLI authentication is separate from the desktop app session and is checked before execution.
- Local probe planning covers bug, feature, migration, refactor, and audit tasks using repository inventories, relevant declared package scripts, and broader Node, Python, and Go checks. A `pr_open` run also receives an approved runtime-owned SHA-bound lifecycle probe. Token-free required-check waiting, review-first repair routing, actionable CI repair, exact review-thread mutation, justified reruns, sticky human decisions, base rebinding, and exact-green completion execute; provider-event wakes remain future work.
- GitHub snapshot capture remains inspection-only; normal push, PR creation, review reply/resolution, and check rerun are distinct journaled side effects of approved remote finish lines. PR editing/reopening, merge, and deployment remain absent and cannot be inferred from a snapshot. Telemetry remains absent. The graphical viewer is deliberately read-only rather than a graph editor. Benchmark infrastructure exists, but repeated dual-host trials, blinded review, published results, and the stable efficiency gate remain incomplete.
- Runtime scope enforcement protects repository and Git state and host profiles restrict exposed tool classes, but Graphcraft does not yet independently attest arbitrary subprocess effects outside the isolated workspace or host-provided OS/network sandbox.
- Redaction, bounded artifact storage, recoverable publication, retention/deletion controls, and storage migration are implemented. Owner-only ACL behavior is accepted for a release only after that exact head passes real Windows CI, and a fully coordinated same-user path-swap adversary remains outside the alpha threat model documented in `SECURITY.md`.
- Wait nodes currently support local time and isolated-worktree filesystem conditions, while pull-request lifecycle waits use persisted bounded polling and backoff. Provider-event wakes remain future work. After a machine restart, the user restarts a persisted run with `graphcraft resume --background`; Graphcraft does not install an auto-start service.
- npm distribution is live, but official Codex and Claude marketplace publication still requires its external submission and review steps. Direct installation from the public GitHub repository remains the registry-independent fallback.
